Next.js — Intercepting Routes

1. Що таке Intercepting Routes?

Intercepting Routes (перехоплення маршрутів) — це механізм Next.js App Router, який дозволяє відображати вміст іншого маршруту всередині поточного інтерфейсу без повного переходу на нову сторінку.

Найпоширеніший приклад — модальні вікна.

Наприклад, користувач перебуває на головній сторінці та натискає на фотографію:

* URL змінюється з / на /photo/123.
* Фотографія відкривається в модальному вікні.
* Поточна сторінка залишається на фоні.
* Якщо оновити браузер, відкриється повноцінна сторінка /photo/123.

Це реалізується через комбінацію Intercepting Routes та Parallel Routes.

⸻

2. Спеціальні позначення маршрутів

Next.js використовує спеціальні позначення для визначення того, звідки потрібно перехопити маршрут.

Позначення	Значення
(.)	Маршрут на тому самому рівні
(..)	Маршрут на один рівень вище
(..)(..)	Маршрут на два рівні вище
(...)	Маршрут від кореня app

Ці позначення працюють відносно дерева URL-маршрутів, а не фізичної структури директорій.

⸻

3. Приклад використання (.)

Розглянемо структуру:

app/
├── layout.tsx
├── page.tsx
├── photo/
│   └── [id]/
│       └── page.tsx
└── @modal/
    ├── default.tsx
    └── (.)photo/
        └── [id]/
            └── page.tsx

Як це працює?

Звичайний маршрут:

/photo/123

Відповідає файлу:

app/photo/[id]/page.tsx

Перехоплений маршрут:

app/@modal/(.)photo/[id]/page.tsx

Він дозволяє показати сторінку фотографії всередині модального вікна.

Поведінка

Дія	Результат
Клік на фотографію через <Link>	Відкривається модальне вікно
Оновлення сторінки	Відкривається повноцінна сторінка
Прямий перехід за URL	Відкривається повноцінна сторінка
Натискання «Назад»	Повернення до попереднього стану

Така поведінка працює за умови правильно налаштованих layout.tsx, паралельного слота та модального інтерфейсу.

⸻

4. Чому використовується (.), а не (..)?

Розглянемо структуру:

app/
├── photo/
│   └── [id]/
│       └── page.tsx
└── @modal/
    └── (.)photo/
        └── [id]/
            └── page.tsx

На перший погляд здається, що потрібно використати (..), оскільки папка photo фізично розташована вище.

Але Next.js не враховує папки Parallel Routes (@modal) під час визначення рівня маршруту.

Тобто:

app/photo
app/@modal/(.)photo

Для маршрутизатора обидва маршрути розташовані на одному рівні.

Тому правильний варіант:

@modal/(.)photo

А не:

@modal/(..)photo

Головне правило

Рівні для Intercepting Routes визначаються за сегментами маршруту, а не за кількістю вкладених директорій.

⸻

5. Чому не можна просто використати @modal/photo?

Тому що @modal і (.) виконують різні завдання.

@modal — Parallel Route

Створює окремий слот для відображення компонента.

Наприклад:

export default function Layout({
  children,
  modal,
}: {
  children: React.ReactNode;
  modal: React.ReactNode;
}) {
  return (
    <>
      {children}
      {modal}
    </>
  );
}

Тут modal — окремий слот, який Next.js може рендерити паралельно з основним контентом.

(.)photo — Intercepting Route

Повідомляє Next.js, що потрібно перехоплювати навігацію до маршруту /photo.

Без (.) директорія @modal/photo не визначатиме перехоплення звичайного маршруту /photo.

Порівняння

Конструкція	Призначення
@modal	Створює паралельний слот
(.)photo	Перехоплює маршрут photo на поточному рівні
@modal/(.)photo	Відображає перехоплений маршрут у слоті modal

⸻

6. Коли використовувати (..)?

Припустимо, структура проєкту виглядає так:

app/
├── dashboard/
│   ├── page.tsx
│   └── @modal/
│       └── (..)photo/
│           └── [id]/
│               └── page.tsx
└── photo/
    └── [id]/
        └── page.tsx

Тут:

* dashboard відповідає маршруту /dashboard.
* photo відповідає маршруту /photo.
* @modal не впливає на рівень URL.

Щоб із /dashboard перехопити /photo, потрібно піднятися на один рівень маршруту.

Тому використовується:

(..)photo

Візуальне пояснення

/                    ← Корінь
├── dashboard         ← Поточний рівень
└── photo             ← Потрібний маршрут

З /dashboard потрібно піднятися до /, а потім перейти до /photo.

Саме це означає (..).

⸻

7. Чи впливають Route Groups на рівні?

Ні.

Наприклад:

app/
├── (public)/
│   └── photo/
│       └── page.tsx
└── @modal/
    └── (.)photo/
        └── page.tsx

Директорія (public) є Route Group.

Вона використовується для логічного групування маршрутів, але не додає сегмент до URL.

Тому:

app/(public)/photo/page.tsx

Відповідає URL:

/photo

І маршрут можна перехопити через:

@modal/(.)photo

⸻

8. Що станеться, якщо неправильно вказати рівень?

Наприклад:

app/
├── photo/
└── @modal/
    └── (..)photo/

У цьому випадку (..) вказує неправильний рівень для перехоплення /photo.

Можливі наслідки:

* Перехоплення не спрацює.
* Модальне вікно не відобразиться.
* Next.js виконає звичайну навігацію.
* За певної конфігурації можна отримати 404.

Конкретна поведінка залежить від структури маршрутів та налаштування Parallel Routes.

⸻

9. Важлива різниця між Soft Navigation та Hard Navigation

Intercepting Routes працюють по-різному залежно від типу навігації.

Soft Navigation

Клієнтська навігація через Next.js Router або <Link>.

<Link href="/photo/123">
  Open photo
</Link>

Next.js може перехопити маршрут та відобразити модальне вікно.

Hard Navigation

Повне завантаження сторінки:

* Введення URL у браузері.
* Оновлення сторінки.
* Відкриття посилання в новій вкладці.

У цьому випадку Next.js завантажує звичайну сторінку /photo/123, а не її перехоплену версію.

Це дозволяє використовувати один URL для двох способів відображення контенту.

⸻

10. Підсумок

Intercepting Routes дозволяють Next.js змінювати спосіб відображення маршруту залежно від контексту навігації.

Основні правила:

1. (.) — перехоплення маршруту на поточному рівні.
2. (..) — перехоплення маршруту на рівень вище.
3. (..)(..) — на два рівні вище.
4. (...) — від кореня app.
5. Папки @modal, @sidebar не враховуються як сегменти URL.
6. Route Groups, наприклад (auth), також не додають рівнів URL.
7. @modal створює паралельний слот, а (.) визначає перехоплення.
8. Перехоплення використовується під час клієнтської навігації.
9. При прямому відкритті URL зазвичай відображається звичайна сторінка.

Важливо: правильна структура має вигляд:

@modal/(.)photo

А не:

(.)/@modal

Позначення (.) повинно бути частиною назви сегмента маршруту, який потрібно перехопити.
